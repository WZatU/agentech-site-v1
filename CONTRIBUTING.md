# Contributing To Agentech Website

This repository is the production source for [agent-tech0316/agentech-site-v1](https://github.com/agent-tech0316/agentech-site-v1). Keep changes reviewable, documented, and safe for the account, billing, robot, and content systems that share this codebase.

## Repository Layout

| Path | Responsibility |
| --- | --- |
| `app/` | Next.js pages, layouts, and server API routes |
| `components/` | Reusable client and server UI |
| `lib/` | Shared business rules and service integrations |
| `docs/` | Operator and engineering documentation |
| `scripts/` | Importers, generators, and robot-computer operations |
| `data/` | Versioned website data generated by approved workflows |
| `public/assets/` | Website media and generated public artifacts |
| `engineer_handoff/` | Isolated prototype/reference implementation for the hardware validator |

Business rules used by multiple routes belong in `lib/`. For example, company-account detection and Software Check credit policy live in `lib/company-accounts.ts`; do not add new hard-coded copies of the company domain.

## Branch And Pull Request Workflow

1. Update `main` with `git pull --ff-only`.
2. Create a focused branch such as `codex/software-check-access` or `feature/news-layout`.
3. Make one coherent change per pull request.
4. Run `npm run check`.
5. Stage only the intended files; avoid `git add .` when unrelated work exists.
6. Push the branch and open a pull request into `main`.

The pull request should explain user-visible behavior, server-side enforcement, data/schema impact, verification performed, and any deployment configuration required.

## Required Checks

```bash
npm run lint
npm run typecheck
npm run build
```

`npm run check` runs all three in order.

For access-control, billing, robot scheduling, or admin changes, verify both the allowed and denied paths. UI state is never sufficient enforcement; the API must validate the same rule.

## Secrets And Generated Files

Never commit:

- `.env` or `.env.local`
- Supabase service-role keys, OpenAI keys, LiveKit secrets, robot credentials, or Dropbox tokens
- `.next/`, logs, `*.tsbuildinfo`, local submission mirrors, or simulator output
- private robot SDK internals or hotspot/SSH details

Use `.env.example` for variable names and safe placeholder/default values only.

## Documentation

Update `README.md` when routes, scripts, environment variables, architecture, or major business behavior changes. Put detailed operator procedures in `docs/` and link them from the README and `docs/documentation-index.md`.
